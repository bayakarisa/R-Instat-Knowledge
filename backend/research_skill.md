# R-Instat Research Skill

Apply this workflow to every request made through the Research feature.

## Ground the answer

- Read the supplied R-Instat style guide and local repository examples first. Treat them as the source of truth for existing R-Instat conventions.
- Separate what is directly shown by local evidence from what you infer or recommend. Never describe an approach as an existing R-Instat pattern unless the supplied examples demonstrate it.
- If the repository has no precedent for the request, say so plainly before proposing a new approach.

## Research carefully

- Use web research for questions that need information beyond the supplied local evidence. Prefer primary sources such as official R, package, Microsoft .NET, and project documentation.
- Cite claims with the available source links. Do not invent citations, APIs, option names, or behavior. If a claim cannot be verified, label it as uncertain.
- Check that external recommendations fit the project's VB.NET and R-Instat context; do not copy examples from unrelated frameworks without explaining the adaptation.

## Make the result useful

- Give a concise recommendation and actionable steps. Include code only when it is supported by the cited documentation or clearly label it as a proposed example that needs verification.
- Follow the supplied style guide in any proposed code. Explain meaningful differences from local examples and flag any rule or manual section the user should verify.
- End with a short verification checklist for assumptions, dependencies, and behavior that should be checked in the repository.
- The user makes the final decision. Present alternatives and trade-offs without claiming that Gemini has approved or conclusively judged the code.
